🛠️ How This Architecture Works (Step-by-Step)

1
User Registration
User submits Name, Email, Password. Password is hashed using bcrypt.
2
Temporary Redis Storage
Registration details & unique token are saved in Redis with a 15-minute TTL. PostgreSQL is NOT touched yet!
3
Email Verification Link
A verification link with the token is emailed (or logged to Docker console).
4
Database Storage & Cleanup
When verified, user details are moved from Redis into PostgreSQL and the Redis temporary key is deleted.
5
Login Enforcement
Only users in PostgreSQL can log in. Pending Redis users are rejected with a prompt to verify first!
